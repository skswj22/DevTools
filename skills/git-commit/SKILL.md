# Git 커밋 메시지 규칙

Conventional Commits 형식 준수 (type: 영문, 본문: 한국어 작성 원칙).<br/>
변경 이력의 신속한 파악 및 type 식별을 통한 변경 성격 즉시 판단 목적.

## 형식

```
type: 한국어 설명
```

- **scope 미사용**: 저장소 규모 특성상 scope 제외 시에도 변경 대상 식별 명확.

## Type 목록

| type | 용도 | 예시 |
|------|------|------|
| `feat` | 신규 기능 추가 | `feat: 닉네임별 모아보기 기능 추가` |
| `fix` | 버그 수정 | `fix: 페이지 범위 입력 시 ValueError 처리` |
| `refactor` | 리팩토링 (동작 변경 없음) | `refactor: main 함수 기능별 분리` |
| `docs` | 문서 변경 (README, HISTORY 등) | `docs: craw_shc_img README 작성` |
| `style` | 코드 스타일/포맷팅 (로직 변경 없음) | `style: 들여쓰기 규칙 통일` |
| `chore` | 빌드, 환경 설정, 패키지 관리 등 | `chore: Docker 이미지 구성 추가` |
| `test` | 테스트 코드 추가 및 수정 | `test: 크롤링 함수 단위 테스트 추가` |

## 작성 원칙

1. **한국어 작성 원칙**: type 영문 표기 외 설명 본문 한국어 작성.
2. **간결성 유지**: 1줄 요약 중심, 50자 내외 권장.
3. **본문 활용 기준**: 제목만으로 상세 맥락 부족 시 빈 줄 삽입 후 변경 사유 기술.
4. **Co-Authored-By 미포함**: 본 저장소 단독 작성 원칙 준수.
5. **단일 목적 커밋**: 단일 커밋 당 1개 목적 할당 (기능 추가와 버그 수정 분리 원칙).

## 본문 작성 기준

제목만으로 변경 사유가 명확할 경우 본문 생략 원칙. 아래 상황에 한해 본문 추가:
- 특정 구현 방식 채택 사유 기술 필요 시
- 다중 파일 변경에 따른 종합적 맥락 전달 필요 시

```
fix: 화이트 닉네임 파일 복귀 시 잘못된 폴더로 이동되는 문제 수정

파일명 _ 분리(split) 시 닉네임 내 _ 포함으로 인한 파싱 오류 발생.
sanitize_filename 함수 내 _ 제거 로직 적용.
```

## 복합 변경 발생 시 처리 기준

코드 수정 및 문서 갱신 병행 시 주된 변경 성격의 type 우선 적용:

- 기능 추가 + README 수정 → `feat`
- 버그 수정 + HISTORY 기록 → `fix`
- 순수 문서 변경 → `docs`
